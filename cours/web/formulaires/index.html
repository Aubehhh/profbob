La balise form : GET et POST

diapos 4 et 5 · 25 min
L'idée. Un formulaire fait passer des données du client vers le serveur. La balise <form> dit comment les envoyer (method) et à quelle page (action).
<form method="get" action="dest.html">
  <!-- champs du formulaire -->
</form>
  • method : GET ou POST.
  • action : la page qui reçoit les données (en général une page PHP).
GETPOST
données écrites en clair dans l'adresse (URL), donc visibles et modifiables à la maindonnées envoyées hors de l'URL : non visibles dans l'adresse, non modifiables directement
pratique pour une recherche, un filtre, un lien partageablepour un mot de passe, des données personnelles, un envoi qui modifie quelque chose
URL envoyée en GET : page?nom1=valeur1&nom2=valeur2 ? sépare l'adresse des données ; & sépare deux champs ; nom = attribut name du champ
Coquilles du cours (diapo 5). L'exemple d'URL « www.url.com/?=variable="42" » s'écrit www.url.com/?variable=42 : le nom, puis =, puis la valeur, sans guillemets. Et POST cache les données de l'adresse, mais ce n'est pas une protection à lui seul : elles restent visibles dans les outils du navigateur. Ce qui chiffre l'envoi, c'est le https.
Exemple corrigé · URL d'un envoi en GET

Un formulaire method="get" action="inscription.php" contient deux champs, name="prenom" (rempli avec Lou) et name="promo" (rempli avec hei). Adresse obtenue ?

Voir la correction
inscription.php?prenom=Lou&promo=hei

Les éléments : input, label et leurs attributs

diapo 6 · 25 min
L'idée. Chaque champ est un <input> dont l'attribut type choisit la forme. Son name devient le nom de la donnée envoyée, et un <label> lui donne un texte cliquable.
type : text, checkbox, radio, range, password, button, submit… id : identifiant (pour le CSS et pour relier le label) name : nom de la variable envoyée au serveur value : valeur par défaut (ou valeur envoyée pour checkbox et radio) <label for="X"> est relié au champ dont l'id vaut X
<label for="nom">Veuillez entrer votre nom :</label>
<input type="text" id="nom" name="myTextbox" value="votre nom" />
Coquille du cours (diapo 6). Le label y est écrit for="name" alors que le champ a id="css_id" : ils ne sont pas reliés. L'attribut for doit avoir exactement la même valeur que l'id du champ (ici, les deux valent « nom »).
Piège : id et name n'ont pas le même rôle. L'id sert dans la page (CSS, label, ancre). Le name sert au serveur : un champ sans name n'est pas envoyé.

Cases à cocher, boutons radio, curseurs et autres types

diapos 7 à 10 · 30 min
L'idée. Checkbox : plusieurs choix possibles, chacun indépendant. Radio : un seul choix parmi un groupe ; c'est le même name qui forme le groupe.
<label for="theme">Mode sombre</label>
<input type="checkbox" name="theme" id="theme" checked />
         → si elle est cochée, envoie theme=on (rien sinon)

<input type="radio" name="promo" id="un" value="hei" />
<label for="un">HEI</label>
<input type="radio" name="promo" id="deux" value="cpi" />
<label for="deux">CPI</label>
         → même name « promo » : un seul choix possible ; envoie promo=hei ou promo=cpi

<input type="range" id="volume" name="volume" min="0" max="11" />
<label for="volume">Volume</label>
Besointype
une couleurcolor
une date, une heure, une semaine, un moisdate, time, week, month, datetime-local
un texte au bon formatemail, url, tel
envoyer un fichierfile
un nombrenumber, range
un mot de passe (caractères masqués)password
plus avancéhidden, reset, search, image
Coquilles du cours (diapos 7 et 8). Dans les labels des boutons radio, il manque le signe égal : <label for="un">. L'attribut switch sur la checkbox n'est pas du HTML standard, il est ignoré par la plupart des navigateurs.

4

Terminer un formulaire : le bouton submit

diapos 11 et 12 · 15 min
L'idée. Le bouton submit agit comme un lien vers la page de l'attribut action, mais il emporte avec lui les données du formulaire.
<button type="submit">Valider</button>
Conclusion du cours. form (method + action), puis des input et un bouton. Pour exploiter les données reçues, il faut en général du PHP côté serveur.
Exemple corrigé · TD 4, exercices 2 et 3

Un formulaire avec un champ « id », un champ « password » masqué et un bouton Valider, testé en GET puis en POST.

Voir la correction
<form method="post" action="https://formtester.goodbytes.be/post.php">
  <label for="id">Identifiant</label>
  <input type="text" id="id" name="id" />
  <label for="password">Mot de passe</label>
  <input type="password" id="password" name="password" />
  <button type="submit">Valider</button>
</form>

En GET (action vers une page d'un TD précédent), l'adresse devient …TD3.html?id=…&password=… : le mot de passe apparaît en clair dans l'URL. En POST, l'adresse ne change pas et la page de test affiche les données reçues. L'énoncé du TD écrit method="get" pour le test POST : il faut bien mettre method="post".

Exercice 3 : on peut mettre une image à la place du texte : <button type="submit"><img src="ok.png" alt="Valider" /></button>. Le bouton devient l'image, et un clic envoie toujours le formulaire.
