Le web : client, serveur et LAMP

diapos 3 à 10 · 25 min
L'idée. Le web repose sur un dialogue : un client (ton navigateur) demande une page, un serveur la lui envoie. Chaque brique de la pile LAMP règle un problème précis.
ProblèmeSolutionBrique
Transmettre une informationle client demande, le possesseur envoie, le client confirme la réception (transmission par paquets)ARPAnet, puis Linux comme système
Proposer plusieurs pagesun programme (le serveur) envoie le fichier demandé ; on passe d'un fichier à l'autre par un lien hypertexteApache
Avoir des pages à jourgénérer la page HTML à la volée, au moment de la demande (elle n'est pas enregistrée sur le serveur)PHP
Conserver des donnéesles ranger dans une base de donnéesMySQL
LAMP = Linux + Apache + MySQL + PHP. Back-end : le serveur envoie les bonnes informations (bases de données, architecture). Front-end : le client affiche correctement (design, interactivité). C'est le front-end qu'on fait dans ce cours.
  • Web 1.0 : pages statiques ou dynamiques (sites vitrines, boutiques, pages perso).
  • Web 2.0 : contenu créé par les utilisateurs (YouTube, réseaux sociaux).
  • Web 3.0 (au sens du cours) : contenu personnalisé (recherches et recommandations adaptées à chacun).
  • W3C (World Wide Web Consortium, fondé en 1994) : publie les recommandations du web. Son validateur, validator.w3.org, vérifie un fichier HTML.
Remarque sur l'historique (diapo 4). ARPAnet date de 1969 et n'a pas tourné sur Linux, apparu en 1991. Le web lui-même (HTML et liens hypertextes) a été inventé par Tim Berners-Lee au CERN vers 1990. Retiens surtout la logique « un problème → une brique », c'est elle que le cours veut faire passer.

Un site qui fabrique la page au moment où tu la demandes (avec la date du jour, par exemple) utilise :

PHP génère la page HTML à la volée ; MySQL stocke les données ; Apache envoie les fichiers.
2

Le HTML en quelques mots

diapos 12 à 15 · 15 min
L'idée. Le HTML (HyperText Markup Language) ne calcule rien : il structure l'information d'une page avec des balises, et c'est le navigateur qui l'interprète pour l'afficher.
  • Avantage : très rapide à écrire. Inconvénients : un navigateur différent peut donner un résultat différent, et c'est difficile à déboguer.
  • Versions : XHTML (basé sur XML), DHTML (dynamique), HTML5 (la version actuelle : portabilité, graphismes, couplage avec JavaScript).
  • Outils : un éditeur de texte (le prof utilise Notepad++) et un navigateur (Firefox).
  1. Créer un fichier .html.
  2. Y écrire du texte.
  3. Ouvrir le fichier dans le navigateur : le texte s'affiche. On l'améliore ensuite avec des balises.
Piège. Le cours dit que le HTML est un « langage interprété ». Plus précisément, c'est un langage de balisage : il décrit une page, il ne contient pas d'instructions de calcul comme un programme.
3

Les balises

diapos 17 à 21 · 40 min
L'idée. Une balise double encadre un contenu (elle s'ouvre et se ferme) ; une balise simple se suffit à elle-même. Les attributs, écrits dans la balise ouvrante, la précisent.

                     balise simple (se ferme elle-même)
 Texte en gras      balise double : ouvrante + contenu + fermante
BaliseRôle
<html>déclare le HTML dans le fichier
<b> · <i> · <u>gras (bold) · italique · souligné (underlined)
<br />retour à la ligne (line break)
<a>lien
<h1> … <h6>titres et sous-titres, du plus grand au plus petit
<p>paragraphe
<ul> / <ol> puis <li>liste sans numéros (unordered) / avec numéros (ordered), un <li> par élément
<img />image (balise simple)
<?php ?>insère du code PHP

Attributs. class, src et alt sont des attributs. Pour <img>, src (le chemin de l'image) est nécessaire ; on peut ajouter width, height, border… Pour <a>, le seul attribut nécessaire est href (la destination). Les chemins partent du dossier courant.

Un lien vers une autre page.
Imbrication. On peut ouvrir une balise à l'intérieur de n'importe quelle balise double, à condition de fermer d'abord la plus intérieure : <p><b>…</b></p>, jamais <p><b>…</p></b>. On indente le code pour qu'il reste lisible.
Pièges. Pour être valide en HTML5 (validateur W3C), <img> doit aussi avoir un attribut alt, le texte lu si l'image ne s'affiche pas. Et dans l'exemple d'imbrication de la diapo 20, un champ <input> placé dans un lien <a> est refusé par le validateur : un élément cliquable ne doit pas en contenir un autre.
Exemple corrigé · TD 1, exercices 1 à 4

Une page avec « Hello world », un titre « Mon texte », deux paragraphes dont le premier mot est en gras, et une seconde page avec un lien « Mon autre page ».

Voir la correction

Hello world

Mon texte


Lorem ipsum dolor sit amet, consectetur adipiscing elit…


Sed ut perspiciatis unde omnis iste natus error…




Retour vers Mon autre page

Exercice 3, br contre p. Avec <br />, on passe juste à la ligne. Avec <p>, chaque paragraphe est un bloc séparé, avec un espace au-dessus et en dessous. C'est <p> qu'il faut utiliser pour découper un texte.

Exemple corrigé · TD 1, exercice 5

Placer une image à droite d'un paragraphe de plusieurs lignes.

Voir la correction

  
  On sait depuis longtemps que travailler avec du texte lisible…

float:right pousse l'image à droite et le texte coule autour. Les valeurs d'attributs s'écrivent entre guillemets (width="200").
