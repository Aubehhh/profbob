1

Ne plus bloquer le programme : millis()

diapos 27 à 30 · 35 min
L'idée. Pendant un delay(), le programme est figé : il ne voit pas un autre bouton. Avec millis(), on note l'heure d'un événement et, à chaque tour de loop, on regarde si le temps voulu est écoulé.
millis() : nombre de millisecondes écoulées depuis le démarrage du programme (unsigned long) Principe : à l'appui → temps1 = millis() et LED allumée à chaque tour → si millis() > temps1 + durée, LED éteinte
void loop() {
  if (digitalRead(button1) == HIGH) {
    digitalWrite(led1, HIGH);
    time1 = millis();               // on retient l'instant de l'appui
  }
  if (digitalRead(button2) == HIGH) {
    digitalWrite(led2, HIGH);
    time2 = millis();
  }
  if (time1 + 1000 < millis()) digitalWrite(led1, LOW);   // 1 s après l'appui
  if (time2 + 1000 < millis()) digitalWrite(led2, LOW);
}
Exemple corrigé · scénario des diapos 29 et 30

Bouton 1 appuyé à 1200 ms, bouton 2 à 1500 ms, puis à nouveau le bouton 1 à 2000 ms. Chaque LED reste allumée 1000 ms après le dernier appui sur son bouton.

Voir la correction
Sans le 2ᵉ appui : LED 1 éteinte à 1200 + 1000 = 2200 ms ; LED 2 éteinte à 1500 + 1000 = 2500 ms Avec le 2ᵉ appui à 2000 ms : time1 = 2000 → LED 1 éteinte à 3000 ms ; LED 2 toujours à 2500 ms

Avec delay(), la LED 2 ne se serait même pas allumée : le programme était bloqué pendant la seconde de la LED 1.

Exemple corrigé · TD 3 : trois LED à des rythmes différents
Voir la correction
unsigned long previousTimeR = 0;
unsigned long intervalR = 700;     // la LED rouge change d'état toutes les 700 ms
bool ledStateR = LOW;

void loop() {
  unsigned long now = millis();
  if (now - previousTimeR > intervalR) {
    previousTimeR = now;
    ledStateR = !ledStateR;          // on inverse l'état
    digitalWrite(LedRouge, ledStateR);
  }
  // même bloc pour l'orange (1300 ms) et la verte (1700 ms)
}

Les trois LED clignotent chacune à leur rythme, en même temps, sans aucun delay(). On utilise des unsigned long : un int (16 bits) déborderait au bout de 32,8 s.

Les interruptions

diapos 31 à 33 · 35 min
L'idée. Au lieu de vérifier un bouton à chaque tour de loop, on demande au microcontrôleur de nous prévenir : dès que le port change, il interrompt le programme, exécute une petite fonction, puis reprend.
volatile bool value = LOW;

void setup() {
  pinMode(led, OUTPUT);
  pinMode(button, INPUT);
  attachInterrupt(digitalPinToInterrupt(button), blink, CHANGE);   // toujours dans setup()
}

void loop() {
  digitalWrite(led, value);
}

void blink() {          // ISR : courte, sans valeur de retour, sans delay()
  value = !value;
}
attachInterrupt(port surveillé, fonction ISR, mode) LOW tant que le port est à l'état bas CHANGE à chaque changement d'état RISING quand le port passe de BAS à HAUT (front montant) FALLING quand le port passe de HAUT à BAS (front descendant) Si une interruption arrive pendant qu'une autre s'exécute, elle attend la fin de la première.
Coquille du cours (diapo 31). Sur l'Uno, les ports d'interruption sont les ports 2 et 3 (comme le dit la diapo 24 du chapitre 1). « 0 et 1 » sont les numéros d'interruption correspondants (INT0, INT1), pas les ports : écris digitalPinToInterrupt(2) pour éviter la confusion.
Pièges du TD 3 (compteur d'appuis).
  • attachInterrupt se place dans setup(), une seule fois, et non dans loop().
  • Une variable modifiée dans l'ISR doit être déclarée volatile (volatile int compteur = 0;).
  • On n'écrit pas sur l'écran LCD dans l'ISR, car c'est trop long : l'ISR incrémente le compteur, et loop() s'occupe de l'affichage.

Entrée analogique et sortie PWM

diapos 34 à 38 · 40 min
L'idée. En entrée, le convertisseur transforme une tension de 0 à 5 V en un nombre de 0 à 1023. En sortie, on ne sait faire que 0 ou 5 V : on simule une tension intermédiaire en alternant très vite (PWM), et c'est la moyenne qui compte.
analogRead(A0) port A0 à A5 → valeur sur 10 bits, de 0 à 1023 valeur ≈ U × 1023 / 5 analogWrite(port, état) ports ~ seulement : 3, 5, 6, 9, 10, 11 → état sur 8 bits, de 0 à 255 rapport cyclique α = état / 255 = durée à 5 V / période tension moyenne = α × 5 V (analogWrite(motor, 150) : α = 59 %, soit 2,94 V)
analogWrite064127191255
rapport cyclique0 %25 %50 %75 %100 %
tension moyenne0 V1,25 V2,5 V3,75 V5 V
Exemple corrigé · exercice des diapos 37 et 38

Lire un capteur (0 à 1023) et transmettre la valeur à un moteur (0 à 255).

Voir la correction
int motor = 6;
int sensor = A0;
int value = 0;

void setup() {
  pinMode(motor, OUTPUT);
  pinMode(sensor, INPUT);
}

void loop() {
  value = analogRead(sensor);          // 0 à 1023
  value = value / 4;                   // ou map(value, 0, 1023, 0, 255)
  analogWrite(motor, value);           // 0 à 255
}

Diviser par 4 donne 0 à 255 (1023 / 4 = 255 en division entière).

Coquille du cours (diapo 38) : la division entière. La correction écrit value = value * (255/1023);. Entre deux entiers, 255/1023 vaut 0 en C : le moteur reçoit toujours 0. Il faut multiplier d'abord (value * 255 / 1023, en long, car 1023 × 255 dépasse la limite d'un int), diviser par 4, ou utiliser map().

Interruptions internes : les timers

diapos 39 à 43 · 35 min
L'idée. Un timer est un registre qui compte tout seul, au rythme de l'horloge, pendant que le programme fait autre chose. Quand il déborde (ou atteint une valeur choisie), il lève un drapeau qui peut déclencher une interruption.
Horloge 16 MHz : un coup tous les 1/16×10⁶ = 62,5 ns Timer 8 bits : compte de 0 à 255, puis déborde (overflow) et repart à 0 débordement tous les 256 × 62,5 ns = 16 µs Prédiviseur N : divise la fréquence → durée d'un pas = N / 16 MHz période de débordement = 256 × N / 16×10⁶ (N = 1024 : 16,4 ms, soit environ 61 Hz)

  • Registres du Timer2 : TCNT2 (valeur du compteur), TCCR2B (contrôle, dont le prédiviseur), TIFR2 (drapeaux), TIMSK2 (autoriser les interruptions), OCR2A / OCR2B (valeurs de comparaison).
  • Mode normal : le timer compte jusqu'à son maximum (255), signale le débordement et repart de 0.
  • Mode CTC (Clear Timer on Compare) : il compte jusqu'à une valeur choisie (par exemple 175), signale puis repart de 0. On règle ainsi une période précise.
Exemple corrigé · périodes d'un timer 8 bits
Voir la correction
N = 64 : pas = 64 / 16×10⁶ = 4 µs ; débordement = 256 × 4 µs = 1,024 ms N = 1024 : pas = 64 µs ; débordement = 256 × 64 µs = 16,384 ms (≈ 61 Hz) CTC à 175 avec N = 1024 : 176 pas (0 à 175) × 64 µs = 11,264 ms
Piège. Le timer compte de 0 à 255, ce qui fait 256 pas, pas 255. Et en CTC jusqu'à OCR, il y a OCR + 1 pas.

Quiz de révision tout le chapitre

Réponses

Les 3 structures de contrôle : if… else, while, for. Remplacer delay() : millis(). Réagir à un événement : les interruptions. Ports analogiques : A0 à A5 en entrée, 3, 5, 6, 9, 10, 11 (~) en sortie PWM.

TD 3 · chronomètre sur l'écran LCD section 1

Méthode

Compte des dixièmes de seconde, puis convertis : 10 dixièmes = 1 s, 60 s = 1 min, 60 min = 1 h. Un if suffit à chaque passage (if (d >= 10) { d -= 10; s++; }), il n'y a pas besoin de boucle for. Pour une vraie précision, utilise millis() plutôt que delay(100) : le temps d'affichage s'ajoute à chaque tour.
